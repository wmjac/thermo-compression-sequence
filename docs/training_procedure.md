## Preserved training behavior

The encoder uses 20 amino-acid tokens, embedding dimension 16, two attention
heads, feedforward width 48, three Transformer layers, ReLU activation in the
Transformer, dropout 0.1, and positional capacity 50. It averages residue
features and then averages the forward and reversed sequence encodings. The
latent head has width d. The decoder uses MLP widths d -> 128 -> 64 -> d(d+1)/2
with SiLU between hidden layers and a symmetric matrix G for its free-energy
form. The original parameter-key names `model1` and `model3` are preserved.

The batch-size grid is [2048], learning-rate grid [1e-3, 5e-3, 1e-2], with five
independent restarts per grid point per fold. Adam settings match the supplied
PyTorch defaults: betas (0.9, 0.999), epsilon 1e-8, no weight decay, no AMSGrad.
Training shuffles the DataLoader and validation does not. Training loss is the
arithmetic mean of minibatch scalar losses.

Warmup is **100 epochs**, or `100 * len(train_loader)` optimizer steps. This
follows the actual code; its comments describing 200 steps do not match execution.
The LambdaLR multiplier is `(step+1)/warmup_steps` during warmup, then one.
The scheduler steps after each optimizer step. Gradients are clipped to norm one.
Maximum epochs are 20000 and stopping patience is 500.

During validation the model is in evaluation mode, parameter gradients are
disabled, and differentiation needed for pressure remains enabled. Validation
loss is the mean of minibatch means, giving the final short minibatch the same
weight as a full one. A checkpoint is updated only when

    validation_loss < recorded_best - 1e-4.

That same update resets patience. Smaller improvements do not update the
recorded best. The selected trial score is the loss of its retained checkpoint,
not a separately recomputed absolute minimum over its raw epoch history.

The original loss divides an atm pressure residual by
`0.1*k_B*T*1e27/101325 * sum(legacy_concentration)`. Since legacy concentration
is ten times physical nm^-3 concentration, conversion gives exactly the
dimensionless physical pressure loss now used at ingestion.

## Explicit refactor changes

These implement the agreed requirements:

1. Pool multiple JSON batches and create reproducible random system-level folds;
   save assignments shared by all dimensions, candidates, and restarts.
2. Read units and nominal temperature from each JSON; convert immediately. The
   old data-loader factor of ten is absent because incoming physical density is
   already converted. The decoder reference scale remains part of the model.
3. Use the repository's differentiable free-energy decoder implementation and
   its parameterization. Numerical equivalence checks compare to both the
   repository model and Bethany's training model.
4. Replace rounded TSV selection values with full-precision JSON results. The
   original helper wrote four decimal places, which could change ranking.
5. Retain k/F distinct candidates per fold. For k=F, this is Bethany's one-best-
   per-fold rule. For k>F, retain the next-best distinct candidates in each fold.
6. Use reproducible trial seeds generated by NumPy SeedSequence from the base
   seed, dimension, fold, batch-grid index, learning-rate index, and restart.
   The original scripts did not record equivalent seeds.
7. Execute candidates sequentially on the allocated GPU and default to zero
   DataLoader workers for the one-CPU MIG environment. Worker/pinning choices
   are explicit and recorded; prefetch/persistence are inactive with zero workers.
8. Pad component slots with zero concentrations to batch mixtures with arbitrary
   numbers of distinct components. Sequence lengths are not padded by this model.
   Padded species are encoded but contribute zero density; this preserves the
   sum-of-component-features formula. Dropout RNG consumption can depend on batch
   component counts; historical stochastic trajectories are not recreated.
9. Save separate histories, full best/last continuation states, input/source
   snapshots, and runtime provenance. This removes the original overwritten
   restart-history filenames and adds epoch-boundary continuation.
10. Report sample-mean held-out evaluation separately from the checkpoint metric.
    Validation predictions use only models whose training excluded that fold.

Selection ranks by (retained validation loss, selected epoch, restart, trial ID).
The first three keys preserve the supplied selector's priorities; trial ID is a
deterministic final tie break. Selection does not round scores, duplicate models,
or use test loss. Every best/last checkpoint includes optimizer, scheduler,
patience, histories, RNG states, and its complete trial configuration.

## Canonicalization behavior

Mixture sampling follows the original truncated GEM construction, including
renormalization and truncation to the available sequence count when needed.
The sequence pool and its ordering are explicit. Uniform total concentration is
in nm^-3. Sampling indices, weights, and total concentrations are saved.

The default metric estimate preserves the original **mean of batch means**.
With an incomplete final batch this differs from averaging individual samples;
`--metric-aggregation sample-mean` is an explicit alternative. The production
example uses 50000 samples in batches of 2000, so the two aggregations coincide.
Gradient evaluation is vectorized within a batch; samples and formulas are
unchanged. Accumulation and linear algebra use float64, as in the reference.

PCA is uncentered, axis signs use nonnegative means, and Procrustes uses only
orthogonal transformations. The ensemble size is generalized from the original
hard-coded five. All transformation constituents and inverse transforms are
saved. Singular metrics cause an explicit failure rather than implicit reduction
or regularization. Basis changes preserve each model's decoder and pressure.

## Extending the model

`data.py` owns physical records and mixture parsing; it imposes no residue-count
restriction or token vocabulary. `models/fixed_length_transformer_mlp.py` owns
`SEQUENCE_LENGTH`, residue validation, tokenization, collation, architecture,
model metadata, optimizer/scheduler factories, and its training protocol.

A replacement model module supplies:

    training_protocol()
    validate_sequences(sequences)
    collate_records(records, dtype)
    build_model(dimension, dtype)
    model_metadata()
    build_optimizer(model, learning_rate, protocol)
    build_scheduler(optimizer, steps_per_epoch, protocol)

The returned model supplies `encode_sequences`, `mixture_latent`,
`thermodynamics`, and a forward method returning its excess thermodynamic terms.
See `models/interface.py`. A variable-length encoder can implement padding/masks
inside its own collation and encoder without changing the physical loader or
canonicalization/evaluation routines. Model metadata is checked at loading;
architecture changes should increment its version.
